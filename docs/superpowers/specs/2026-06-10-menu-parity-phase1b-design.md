# Menu parity — Phase 1b design (2026-06-10)

## Goal

Land the two menu-event parity scenarios that Phase 1 deferred:

- **`popup_winmsg_credits_dismiss`** — dismiss the any-key popups `WIN_Msg`
  ("No Pilots to Load") and `WIN_Credits`.
- **`load_navigate_and_load`** — open the LOAD window with committed pilot
  fixtures, cycle pilots (NEXT/PREV), and load one → Hangar.

Both verified C↔Godot via the per-keypress menu-event stream
(`RAPTOR_MENU_OUT` → `parity_diff.py --menu`), added to the committed golden set
and picked up automatically by the CI sweep gate in `ci/full.sh` (wired
`15b76f6`). This continues the phased plan in
`docs/superpowers/specs/2026-06-09-menu-parity-full-coverage-design.md`.

## Why these were deferred (and what changed)

Phase 1 (`docs/superpowers/plans/2026-06-09-menu-parity-phase0-1.md`) deferred
both. Re-scoping (two read-only exploration passes, 2026-06-10) corrected two
assumptions:

1. **`load` has no "C-`.FIL` vs Godot-JSON" format problem.** Godot's
   `PilotSaveStore` (`src/Sim/PilotSaveStore.cs`) reads/writes the *identical*
   encrypted binary `CHAR####.FIL` format as C (same `"CASTLE"` key, same
   `SEED=0x0019`, same 88-byte header, same per-record encryption). **One fixture
   file serves both sides.** And C's `RAP_LoadWin` is *already* parity-hooked
   (`LOADSAVE.C:506-509`), so no new C code is needed for `load`.
2. **The `popup` scenario is the one that needs new C code.** The any-key popups
   wait in `IMS_WaitTimed` (`GFX/IMSAPI.C:126`), **not** `SWD_Dialog`, so they
   never call `raptor_parity_menu_event`. There is no C golden for them today.

## Constraints (inherited, non-negotiable)

1. **30-frame key gaps are mandatory** — C menu input is wall-clock-paced; keys a
   few frames apart register nondeterministically. Every script obeys this.
2. **No ad-hoc windowed C runs** — the C binary needs a real SDL renderer and
   steals focus (memory `no-windowed-c-binary-runs`). All golden captures are
   **batched** into one unattended sweep the user runs when away.
3. `src/Sim/` rules apply (no `delta`/`_Process`/engine-RNG/wall-clock). Harness
   code lives in `src/Test/`, the C hooks in `port/`/`SOURCE/`.
4. The comparator's exact-matched fields are `win`, `selected_item`,
   `event_index`, `kind`; `screen`/`scancode`/`x`/`y`/`button` are advisory.

## Scenario 1 — `popup_winmsg_credits_dismiss`

**Save state:** empty save dir (no fixture). This is what makes `Return` on LOAD
fall into the "No Pilots to Load" branch (`LOADSAVE.C:493-495` →
`WINDOWS.C:2138-2141`), giving a free, faithful `WIN_Msg` trigger.

**Script** (dosraptor `tests/scripts/popup_winmsg_credits_dismiss.txt`, 30-frame
gaps): from the main menu —
1. `Down` → highlight LOAD (item 1).
2. `Return` → no pilots → `WIN_Msg("No Pilots to Load")`.
3. dismiss key → back to menu.
4. navigate to CREDITS (item 4).
5. `Return` → Credits (after the 70-frame Godot fade — script waits past it).
6. dismiss key → back to menu.
7. `quit`.

**New C hooks** (`SOURCE/WINDOWS.C`, additive, emit-only):
- `WIN_Credits` (~line 520): after `rval = IMS_WaitTimed(25)`, before
  `raptor_parity_set_win_state(0)` — `raptor_parity_menu_event(0, 1, rval?1:0, 0,
  0, 0)`. Emits `kind=key`, `win="CREDITS"`, `selected_item=0`.
- `WIN_Msg` (~line 161): capture `rval = IMS_WaitTimed(10)`, then after it and
  before `SWD_DestroyWindow` — `raptor_parity_menu_event(0, 1, rval?1:0, 0, 0,
  0)`. Emits `win="MENU"` (parent context), `selected_item=0`. (The scancode arg
  is advisory; `rval?1:0` is a "dismissed-by-key" sentinel.)

`WIN_Order`/`WIN_Pause` are explicitly **out of scope** — the main-menu "Order"
item opens `HELP_Win` (already covered as HELP), and the real `WinState.Order`
path is in-game only and unimplemented in Godot (the separate, still-blocked
`popup_pause_order_dismiss` scenario).

**Godot change:** a popup dismiss currently emits `EffectiveSelectedItem()` =
`CurrentItem` (e.g. 4 for the Credits item) — diverging from C's `0`. Special-case
the Credits / `_inWinMsg` dismiss emit to report `selected_item=0`, matching the
"no cursor in a popup" sentinel. Emit path unchanged
(`PlaythroughDriver` → `ParityEmitter.EmitMenuEvent`).

## Scenario 2 — `load_navigate_and_load`

**Save state:** committed fixture `tests/parity/menu_fixtures/load_navigate_and_load/`
with `CHAR0000.FIL`, `CHAR0001.FIL`, `CHAR0002.FIL` (3 pilots → exercises NEXT
forward, PREV back, wrap at both ends). Generated by a small tool/test calling
`PilotSaveStore.Save` 3× (the resulting `.FIL` loads identically in both
engines). The runner copies the fixture into the hermetic `RAPTOR_SAVE_DIR`
(`run_menu_event_parity.sh:112-115`).

**Script** (dosraptor `tests/scripts/load_navigate_and_load.txt`, 30-frame gaps):
from the main menu — `Down` → LOAD, `Return` → LOAD window, then NEXT/PREV to
cycle the shown pilot (forward, back, wrap), then `LOAD` to confirm → Hangar,
`quit`.

**C side:** no new code — `RAP_LoadWin` already emits `active_field-1` per
keypress (`LOADSAVE.C:506-509`).

**Godot change (pending the golden):** align `EffectiveSelectedItem()` for the
LoadMission sub-state. C's cursor is the *button* (`LOAD`/`NEXT`/`PREV`/`DEL`/
`CANCEL`, `active_field` initialised to `LOAD_LOAD=5`); Godot's
`LoadMissionPanel.SelectedIndex` is the *pilot-list index* (0-based). These are
different number spaces. The captured C golden is the oracle for what to align
to. **Open risk:** if the two cursor models produce structurally different event
streams (not just an index offset), Godot's load UI needs a faithful touch-up —
surfaced as its own finding, not silently forced to pass.

## Properties / Invariants

- **Event-stream equality**: each scenario's Godot menu-event stream equals the
  committed C golden on `win`/`selected_item`/`event_index`/`kind` (exact);
  `screen`/`scancode`/`x`/`y`/`button` advisory. *Domain:* `parity_diff.py
  --menu` over the two new goldens.
- **One event per processed keypress**: each script keypress that reaches a
  hooked path emits exactly one event per side; order and count match
  (`event_index` monotonic and aligned by index). *Domain:* both engines' emit.
- **Popup-dismiss sentinel**: a Credits or `WIN_Msg` dismiss emits
  `selected_item=0` on both sides (no cursor in a popup). *Domain:* the C hooks
  in `WIN_Credits`/`WIN_Msg` + the Godot popup-dismiss emit.
- **Fixture round-trips (oracle)**: a `CHAR####.FIL` written by
  `PilotSaveStore.Save` loads identically through C `RAP_LoadPlayer` and Godot
  `PilotSaveStore.LoadAll` — same name, callsign, score, id_pic. *Domain:* the
  shared encrypted `CHAR####.FIL` format.
- **Hermeticity**: scenario output depends only on `RAPTOR_SAVE_DIR` contents +
  the script, never on ambient pilot files. *Domain:* `run_menu_event_parity.sh`.
- **C-reference inertness**: the new C hooks only write to `RAPTOR_MENU_OUT` and
  do not change any game/menu behavior. *Domain:* dosraptor `WIN_Credits`/
  `WIN_Msg`.
